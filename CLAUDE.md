## 1. What This Repository Is

Midgard is **embodied law** — `Norse.Infrastructure`: the concrete implementations of Asgard's contracts. Persistence, messaging, caching, and external integrations live here — the `DbContext` family, EF conventions, repository implementations (including temporal), `JsonControllerBase<TService>`, the mediator runtime, and UI composition. In the dependency chain it rides on Asgard, Svartálfheim, and Urðarbrunnr; Yggdrasil and everything above rides on it.

**`Norse.Infrastructure.Migrations` is live** — `MigrationRunnerService` and `AddNorseMigrationsRunner()` shipped, merged, tagged, and published to NuGet as Task 2 of the cross-realm migrations framework rollout (`../Glitnir/docs/Platform/plans/2026-06-28-migrations-framework-identity-schema.md`). It is the hosted service every Norse migrations service calls through, indirectly, via the source-generated `AddNorseMigrations()` from Urðarbrunnr: resolve every registered `IMigrationContributor`, run them, call `IHostApplicationLifetime.StopApplication()` on success, throw hard on any failure. No swallowed exceptions, no partial migration, no silent fallback.

**`Infrastructure.Web.Server`/`.Web.Client` are also live** — the gRPC mediator transport and the `IDeferredSignIn` implementation against Asgard's `Abstractions.Web.Server` contract. The gateway-generator machinery this section used to describe is retired outright (`../Glitnir/docs/Platform/specs/2026-07-27-mediator-pipeline-retires-gateway-design.md`): `AddNorsePipeline()` registers the four behaviors (`TelemetryBehavior`/`ExceptionTranslationBehavior`/`AuthorizationBehavior`/`ValidationBehavior`, `Mediator/` folder) plus `Sender` and `IPrincipalAccessor` as plain DI citizens with ordinary constructor injection — no generator constructs them, so no per-consumer `InternalsVisibleTo` grant is needed anymore; the one that used to gate `Norse.Hosting.Web.Server` access is deleted. The gRPC transport itself is a three-interceptor stack (`UnhandledExceptionInterceptor` → `PrincipalSeedingInterceptor` → `OutcomeServerInterceptor`, law order) — `OutcomeServerInterceptor` is now actually registered, closing the gap the 2026-07-27 audit found (it had sat implemented, unit-tested, and dead). `OutcomeClientInterceptor` decodes the wire response back into `Outcome<T>` on the client side. Two `gen/` wiring generators land here too: `MapNorseGrpcServices` (server-side, `UseGrpcWeb`/`EnableGrpcWeb`) and `AddNorseGrpcClients` (client-side channel + proxy registration) — discovery-and-wiring generators, never composition, per §2.7 of the design doc. **`Infrastructure.Web.Grpc` is live too** — the shared wire-law project (`Norse.Infrastructure.Web.Grpc`, PR #41) carrying `IdentifierSerializers`: every contract member swept to CompatibilityLevel 300 via an `AfterApplyDefaultBehaviour` sweep, `Guid`/`Guid?` members wired as bare 16-byte RFC 9562 `bytes` fields via `DataFormat.FixedSize`, and custom scalar serializers for `SequentialGuid`/`DeterministicGuid`. Both `Infrastructure.Web.Client` and `Infrastructure.Web.Server` reference it, and the generated client/server wiring registers it against `RuntimeTypeModel.Default` — Midgard's one and only edge to Svartálfheim's `Norse.Primitives`. The remaining `DbContext` family and repository implementations are still unconverged; no specs have landed for them yet. **`Infrastructure.Components.Theme`/`.Theme.FluentUI` are live** — the first slice of "UI composition": app-wide theme bootstrapping, seeded from Naglfar's generated token package (`../Glitnir/docs/Platform/specs/2026-07-11-blazor-component-architecture-design.md`, Addendum 2026-07-12). **`Infrastructure.Backend` is live too** — Midgard's shared server-side assembly (the mirror of Asgard's `Abstractions.Backend`), home to concerns both `{Realm}.Web.Server` and `{Realm}.Worker` consume; no per-functional-group packages (ruled 2026-08-03). First resident, under `Serialization/`: `SystemTextJsonSerializer`/`SerializerProvider` and `AddNorseSerialization()`, the STJ machinery behind Asgard's format-agnostic serialization seam (`ISerializer`/`ISerializerProvider`/`NamingStrategy` in `Abstractions.Backend`), Task 2 of the seam rollout (`../Glitnir/docs/Platform/specs/2026-08-03-serialization-seam-design.md`) — STJ stays caged here, inside the wire border, per NORSE070; Himinbjörg's personal-data download is the first pending consumer. `Keys/` also lands here — `DevelopmentSubjectKeyStore` and `AddNorseDevelopmentKeys()`, a file-backed, dev-grade-only implementation of Asgard's `ISubjectKeyStore`/`ILookupKeyRing` key seam (keys rest unwrapped on local disk; never a production path), per the 2026-08-03 PII primitives / identity erasure seam plan. The other half of "UI composition" — the mechanism that composes N registered dashboard widgets into a rendered, user-arranged layout — remains unconverged. Before writing any new code outside an already-converged slice (`Infrastructure.Migrations`, `Infrastructure.Web.Server`/`.Web.Client`, `Infrastructure.Web.Grpc`, `Infrastructure.Components.Theme`/`.Theme.FluentUI`, `Infrastructure.Backend`): brainstorm → spec → plan, recorded in `../Glitnir/docs/Midgard/`, per the org's spec-first discipline. Do not scaffold a project structure ahead of a converged spec.
